# Анализ состояния ТКШ и РЩ

YOLO26n находит шкафы и распределительные щиты. MobileNetV3 Small получает вырезки по найденным рамкам и определяет состояние. Обе модели загружаются из локальных весов один раз на процесс. FastAPI вызывает этот каскад при загрузке фото, сохраняет проверку в БД и отдаёт ссылку на изображение с рамками.

## Интерфейс и показ на защите

После запуска бэкенда откройте `http://127.0.0.1:8000/demo/`. Интерфейс загружает демонстрационный кадр ТКШ. Нажмите «Проанализировать кадр», чтобы получить результат от моделей. Переключатели «Исходник» и «С разметкой» меняют вид фотографии. В «Журнале» можно открыть сохранённую проверку, а кнопка «Экспорт CSV» выгружает обнаруженные дефекты.

На показе можно использовать встроенное видео на слайде 4 или отдельный MP4 с подписями. В ролике показан реальный ответ модели на валидационном кадре. ## Запуск бэкенда

Из корня проекта с Docker Desktop:

```powershell
docker compose up --build
curl.exe -F "file=@C:\path\to\photo.jpg" http://localhost:8000/api/v1/analyze
```

Документация API доступна по адресу `http://localhost:8000/docs`. Compose монтирует каталог `weights` только для чтения. Бэкенд по умолчанию загружает `detector_v2.pt` и `classifier_v2.pt` из этого каталога.

Для проверки без Docker и PostgreSQL можно использовать SQLite:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:DATABASE_URL = 'sqlite:///./.work/demo.db'
$env:YOLO_CONFIG_DIR = "$PWD/.work/yolo-config"
$env:YOLO_OFFLINE = 'true'
New-Item -ItemType Directory -Force .work | Out-Null
.\.venv\Scripts\python.exe -m uvicorn main:app
```

Если PostgreSQL уже содержит старую таблицу `detections`, добавьте столбцы для координат перед запуском обновлённого бэкенда:

```sql
ALTER TABLE detections
    ADD COLUMN IF NOT EXISTS latitude DOUBLE PRECISION,
    ADD COLUMN IF NOT EXISTS longitude DOUBLE PRECISION;
```

### Контракт

- `POST /api/v1/analyze` принимает multipart-поле `file` и возвращает запись проверки с массивом `detections`. При отсутствии объектов массив пуст. При недоступных весах сервер отвечает HTTP 503.
- `object_type` принимает значения «ТКШ» или «РЩ». `status` передаёт результат классификации или значение «Требуется проверка» при низкой уверенности. `needs_repair` указывает на обнаруженный дефект, а `requires_inspection` выставляется для дефектов и результатов, требующих ручной проверки.
- `confidence` в API содержит оценку детектора. `bbox` содержит абсолютные координаты `[x1, y1, x2, y2]` на ориентированном по EXIF изображении. Правая и нижняя границы могут совпадать с шириной и высотой изображения. Координаты места съёмки берутся из EXIF при наличии.
- `predictor.predict_image(PIL.Image)` возвращает список объектов схемы бэкенда. `predictor.analyze(PIL.Image, image_id=...)` возвращает словарь с размерами, рамками, кодами типов, двумя оценками уверенности и полем `classification`. Ориентацию изображения перед прямым вызовом задаёт вызывающий код. CLI и HTTP применяют ориентацию по EXIF.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m predictor "C:\path\to\photo.jpg"
```

Настройки можно задать через переменные окружения или `.env`. `DETECTOR_WEIGHTS` и `CLASSIFIER_WEIGHTS` задают пути к файлам. `ML_DEVICE` поддерживает `auto`, `cpu` и `cuda:0`. Порог детекции `CONFIDENCE_THRESHOLD=0.25` выбран по F1 на валидационных кадрах. По умолчанию детектор анализирует полный кадр при `DETECTOR_IMAGE_SIZE=384`. `CLASSIFIER_THRESHOLD` переопределяет порог 0,55, записанный в весах v2. После замены весов или настроек перезапустите процесс.

## Данные и обучение

В двух корневых архивах 62 изображения. Из них 61 сопоставлено с таблицами Excel по папке и имени. Фото в корне архива представляет тот же вид, что и один из размеченных кадров, с добавленными подписями. В обучающую выборку вошли снимки из шести категорий.

[Предварительная разметка рамок](detector/annotations.json) основана на визуальном осмотре материалов организаторов. Часть фотографий содержит несколько объектов. Состояние присвоено целевому объекту по категории фотографии, а вторичные объекты с неизвестным состоянием участвуют только в обучении детектора. Снимки со сходными ракурсами или признаками одной площадки сгруппированы вручную. Обе модели используют общее разбиение 43 / 8 / 10 кадров. Группы определены по визуальному сходству и именам, поэтому для оценки на новых площадках потребуется отдельная выборка.

```powershell
$env:YOLO_CONFIG_DIR = "$PWD/.work/yolo-config"
$env:YOLO_OFFLINE = 'true'
.\.venv\Scripts\python.exe -X utf8 dataset.py inspect
.\.venv\Scripts\python.exe -X utf8 dataset.py prepare --focus-small --out .work/refined
.\.venv\Scripts\python.exe -m detector.train --data .work/refined/detection.yaml --initial .work/pretrained/yolo26n.pt --output .work/refined/detector26n.pt --recipe small-objects --epochs 48 --imgsz 384 --batch 6 --freeze 5 --patience 16 --threads 4 --eval-split val
.\.venv\Scripts\python.exe -X utf8 evaluate.py --split test --threshold 0.25
```

Перед обучением положите стартовые файлы в `.work/pretrained`. [YOLO26n от Ultralytics](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26n.pt) и [MobileNetV3 Small от PyTorch](https://download.pytorch.org/models/mobilenet_v3_small-047dcff4.pth).

`dataset.py prepare` создаёт разметку, вырезки и общий манифест. Параметр `--focus-small` добавляет 24 приближённых фрагмента в обучающую часть детектора. Для повторной подготовки укажите новый каталог через `--out`. Для экспериментов с весами укажите `--output`. При запуске на GPU укажите совместимые сборки PyTorch и torchvision с CUDA.

На валидации сравнили YOLO26n, YOLO26s и YOLO11s, размеры входа 384, 512 и 640, полный кадр и фрагменты. Переобученный YOLO26n на полном кадре показал лучшие mAP50 и mAP50–95. Для оценки состояния сравнили MobileNetV3 Small, ResNet18 и EfficientNet-B0. В каскаде лучший результат дал MobileNetV3 Small с исходной и расширенной на 18% с каждой стороны рамкой. Модель усредняет вероятности двух вырезок. [Валидация v2](weights/validation_v2.metrics.json).

Классификатор можно дообучить через `classifier.train` или обучить линейную голову на замороженных признаках через `classifier.train_features`. Флаг `--box-jitter` добавляет вырезки со смещённой рамкой при обучении. Параметры команд доступны через `--help`.
